# 20261126100000 — invoices emailed to clients

**What it is for.** BRD v1.4/v1.5 Step 10 and TC28: until Zoho Finance is live, Finance uploads the MAHER invoice
against the work order and emails it to the client from the portal, not WhatsApp. The portal records who sent it,
when and to which addresses, and both Finance and Operations see it on the work order's Invoices tab.

**What it adds.** `finance.invoice_emails` (append-only, one row per email sent) and
`finance.record_invoice_email(...)` (SECURITY DEFINER, service role only). Nothing existing changes.

**Live-safe.** The code live now never touches them. The new code shows no sends, and refuses to send, until this is
applied, so no email can go out unrecorded.

## Apply

Run `supabase/migrations/20261126100000_finance_invoice_emails.sql` in the Supabase SQL editor (one transaction).

## Check

```sql
select (select count(*) from information_schema.tables where table_schema = 'finance' and table_name = 'invoice_emails'),
       (select count(*) from pg_proc p join pg_namespace n on n.oid = p.pronamespace
          where n.nspname = 'finance' and p.proname = 'record_invoice_email'),
       (select relrowsecurity from pg_class where oid = 'finance.invoice_emails'::regclass);
```

Expect `1 | 1 | t`.

## Who the email reaches

The Finance delivery policy decides, per server:

| Setting | Where the invoice email goes |
|---|---|
| `FINANCE_NOTIFY_LIVE=on` | The client addresses Finance entered, and the copies |
| `NOTIFY_REDIRECT_TO=<address>` only | That address alone, "[DEV]" in the subject and a banner naming the client; recorded as a test copy |
| neither | Nothing; the dialog says why |

## Rollback

`docs/finance-reporting/migrations/20261126100000_rollback.sql` (drops the record of sends; the emails already sent
stay sent).
