# 20261021100000_finance_core

A new schema, **`finance`**: the Ready-to-Invoice queue (BRD §5.1). Five tables (`queue_items`,
`queue_item_lines`, `invoices`, `exclusions`, `queue_events`), the `estimate_progress` view, and six
functions (`create_queue_item`, `apply_action`, `request_exclusion`, `decide_exclusion`, `record_invoice`, and
the `append_only` trigger function). Nothing in `public` changes; live `main` reads nothing in `finance`.

The server role can **read** the tables and change them **only through the functions** (which run as their
owner). `fsm` must already be applied (`20261020130000`): the functions read the FSM copy.

Tested on the [harness](../../../scripts/db-harness/README.md): applied twice; `checks/40_p3_finance_core.sql`
runs the BRD's Q-1042 example end to end (41.7 % → 75.0 % → 100 %), TC03–TC06, double-invoicing and stale
clicks refused, the exclusion flow, append-only history, and the server role's access; the post-check below
and the rollback round trip.

## Pre-check (expect `f, t`)

```sql
select to_regnamespace('finance') is not null as finance_schema_exists,
       to_regclass('fsm.line_items') is not null as fsm_ready;
```

## Apply

1. The file, in one transaction. Never `supabase db push`.
2. **Project Settings → API (Data API) → Exposed schemas: add `finance`**, and save (as for `fsm`).

## Post-check (expect one row: `5, 1, 6, 0, f, t, f`)

```sql
select
  (select count(*) from pg_class where relnamespace = 'finance'::regnamespace and relkind = 'r')   as tables,
  (select count(*) from pg_class where relnamespace = 'finance'::regnamespace and relkind = 'v')   as views,
  (select count(*) from pg_proc where pronamespace = 'finance'::regnamespace)                      as functions,
  (select count(*) from information_schema.role_table_grants
     where table_schema = 'finance' and grantee in ('anon', 'authenticated'))                     as api_table_grants,
  has_schema_privilege('anon', 'finance', 'USAGE')
    or has_schema_privilege('authenticated', 'finance', 'USAGE')                                  as api_schema_usage,
  has_schema_privilege('service_role', 'finance', 'USAGE')                                        as server_schema_usage,
  has_table_privilege('service_role', 'finance.invoices', 'INSERT')                               as server_can_write_directly;
```
