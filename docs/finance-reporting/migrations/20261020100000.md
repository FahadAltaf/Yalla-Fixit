# 20261020100000_reporting_platform

Three new tables: `reporting_settings` (one row), `reporting_audit_events` (append-only),
`portal_notifications`. Nothing live `main` uses is changed. Safe before or after this branch's code
deploys: nothing on `main` reads these tables.

Tested on the [harness](../../../scripts/db-harness/README.md): applied twice; checks in
`checks/10_p1_platform.sql`, the post-check below (`05_post_checks.sql`) and the rollback round trip
(`90_rollback_roundtrip.sql`).

## Pre-check (expect one row: `f, f, f, t`)

```sql
select to_regclass('public.reporting_settings') is not null      as settings_exists,
       to_regclass('public.reporting_audit_events') is not null  as audit_exists,
       to_regclass('public.portal_notifications') is not null    as notifications_exists,
       to_regclass('public.user_profile') is not null            as user_profile_exists;
```

If any of the first three is `t`, stop: the migration was applied before. Check the log.

## Apply

The file, in one transaction (SQL editor, or `psql -1 -f`). Never `supabase db push`.

## Post-check (expect one row: `1, t, 0, 2, 5`)

```sql
select
  (select count(*) from public.reporting_settings)                                   as settings_rows,
  (select bool_and(relrowsecurity) from pg_class
     where oid in ('public.reporting_settings'::regclass,
                   'public.reporting_audit_events'::regclass,
                   'public.portal_notifications'::regclass))                          as rls_on,
  (select count(*) from information_schema.role_table_grants
     where table_schema = 'public' and grantee in ('anon', 'authenticated')
       and table_name in ('reporting_settings', 'reporting_audit_events',
                          'portal_notifications'))                                   as api_grants,
  (select count(*) from pg_trigger
     where tgrelid = 'public.reporting_audit_events'::regclass and not tgisinternal) as audit_triggers,
  (select count(*) from pg_indexes
     where schemaname = 'public' and tablename = 'portal_notifications'
       and indexname like 'idx_portal_notifications_%')                              as notification_indexes;
```

Live check: open the portal home page and Scheduling; both load as before.
