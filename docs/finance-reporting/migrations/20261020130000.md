# 20261020130000_fsm_read_model

A new schema, **`fsm`**, holding the portal's read-only copy of Zoho FSM: nine tables (`sync_state`,
`sync_runs`, `estimates`, `estimate_status_events`, `work_orders`, `line_items`, `line_status_events`,
`appointments`, `appointment_resources`) and seven writer functions (`upsert_estimates`, `upsert_work_orders`,
`sync_line_items`, `upsert_appointments`, `set_appointment_crew`, `sync_claim`, `sync_release`). Nothing in
`public` changes, and live `main` reads nothing in `fsm`. Only the server role (`service_role`) is granted
anything in the schema. Safe before or after this branch's code deploys.

Tested on the [harness](../../../scripts/db-harness/README.md): applied twice; checks in
`checks/30_p2_read_model.sql` (older records never overwrite newer ones, replays add no events, removed lines
kept, stale crew reads ignored, the lease), the post-check below, and the rollback round trip.

## Pre-check (expect `f`)

```sql
select to_regnamespace('fsm') is not null as fsm_schema_exists;
```

If `t`, stop: the schema exists already. Check the log.

## Apply

1. The file, in one transaction. Never `supabase db push`.
2. **Project Settings → API (Data API) → Exposed schemas: add `fsm`**, and save. Without this the
   portal's server cannot reach the tables (the API answers "schema must be one of …"). Exposing it opens
   nothing to the browser: the schema grants the browser's roles no access.

## Post-check (expect one row: `9, 3, 7, 0, 0, f, t`)

```sql
select
  (select count(*) from pg_class
     where relnamespace = 'fsm'::regnamespace and relkind = 'r')                       as fsm_tables,
  (select count(*) from fsm.sync_state)                                             as sync_resources,
  (select count(*) from pg_proc where pronamespace = 'fsm'::regnamespace)           as fsm_functions,
  (select count(*) from information_schema.role_table_grants
     where table_schema = 'fsm' and grantee in ('anon', 'authenticated'))           as api_table_grants,
  (select count(*) from pg_proc p
     where p.pronamespace = 'fsm'::regnamespace
       and (has_function_privilege('anon', p.oid, 'EXECUTE')
            or has_function_privilege('authenticated', p.oid, 'EXECUTE')))          as api_executable,
  has_schema_privilege('anon', 'fsm', 'USAGE')
    or has_schema_privilege('authenticated', 'fsm', 'USAGE')                        as api_schema_usage,
  has_schema_privilege('service_role', 'fsm', 'USAGE')                              as server_schema_usage;
```
