# 20261104100000_finance_not_invoiceable_both_sides

Not invoiceable from either side, and queries as a plain conversation (2 Nov).

- **Mark not invoiceable**: Finance or Operations marks a work order not invoiceable at once, with a reason
  (`finance.mark_not_invoiceable`). The other side is told who did it. Refused once any of it is invoiced. A request
  still waiting from the old verification step is closed by the mark.
- **Mark invoiceable**: either side puts it back (`finance.mark_invoiceable`): to Open (In Progress when some of it
  was invoiced before), or to Query Raised while a query on it is open. The other side is told.
- `finance.wo_exclusions` gains who marked it by side, and who undid it (`reverted_*`, `revert_note`).
- `finance.line_events` also allows `exclusion_reverted`.
- **Queries**: `finance.reply_query_thread` is replaced: a reply (`comment`) or closing it (`closed`), by either side.
  No resolved / not resolved, corrected or withdrawn any more. Threads from before keep their history.

Live-safe: nullable columns, a wider check, functions in schema `finance` (nothing on `main` reads it). Idempotent
(applied twice on a throwaway Postgres 15; rollback tested there too). Until it is applied, the page's
"Mark not invoiceable" and "Mark invoiceable" say a database update is needed, and closing a query from the side
that did not raise it is refused.

## Pre-check (expect `f | f | f`)

```sql
select to_regprocedure('finance.mark_not_invoiceable(text, text, text, text, text, text[], uuid, text)') is not null,
       to_regprocedure('finance.mark_invoiceable(text, text, text, uuid, text)') is not null,
       exists (select 1 from information_schema.columns where table_schema = 'finance' and table_name = 'wo_exclusions' and column_name = 'reverted_at');
```

## Post-check (expect `t | t | t | t | t`)

```sql
select to_regprocedure('finance.mark_not_invoiceable(text, text, text, text, text, text[], uuid, text)') is not null,
       to_regprocedure('finance.mark_invoiceable(text, text, text, uuid, text)') is not null,
       exists (select 1 from information_schema.columns where table_schema = 'finance' and table_name = 'wo_exclusions' and column_name = 'reverted_at'),
       position('exclusion_reverted' in pg_get_constraintdef((select oid from pg_constraint where conname = 'line_events_event_type_check'))) > 0,
       position('reply or close' in pg_get_functiondef('finance.reply_query_thread(uuid, text, text, text, uuid, text, uuid, text)'::regprocedure)) > 0;
```

## Rollback

[20261104100000_rollback.sql](20261104100000_rollback.sql): drops the two functions and the new columns, puts back the
reply rules of 20261103100000. Refused while any `exclusion_reverted` event exists (history). Work orders already marked
stay Excluded.

## Note (2 Nov)

As applied, its "already marked", "not marked" and "already closed" refusals used SQLSTATE 40001, which the database
API retries until the gateway times out. Fixed by [20261104110000](20261104110000.md); this file now has the fixed code.
