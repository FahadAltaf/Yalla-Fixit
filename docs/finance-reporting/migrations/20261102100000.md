# 20261102100000_technician_weekly_hours

Each technician's working hours for utilization (2 Nov): besides daily hours (8, 9 or 12 by contract, since
20261028100000), a **weekly hour limit** (e.g. 48 or 60) and **off days per week** (a number, not fixed weekdays).
Set in Scheduling → Technicians. Both are kept in `technician_attribute_history`, so past periods keep the values
of their time.

Live-safe: two nullable columns on `technician_reference`; the history trigger is replaced with the same
behaviour for the two new fields; the history field check is widened. Idempotent. Until it is applied the
technician dialog refuses the two new fields and utilization uses 1 off day a week and no weekly limit.

Note: the trigger function is shared with live `main` (it fires on any update of those columns). Replacing it
keeps exactly the old behaviour for the four existing fields.

## Pre-check (expect `f | f`)

```sql
select exists (select 1 from information_schema.columns where table_schema = 'public' and table_name = 'technician_reference' and column_name = 'weekly_hours'),
       exists (select 1 from information_schema.columns where table_schema = 'public' and table_name = 'technician_reference' and column_name = 'off_days_per_week');
```

## Apply

The file in the SQL editor.

## Post-check (expect `t | t | t`)

```sql
select exists (select 1 from information_schema.columns where table_schema = 'public' and table_name = 'technician_reference' and column_name = 'weekly_hours'),
       exists (select 1 from information_schema.columns where table_schema = 'public' and table_name = 'technician_reference' and column_name = 'off_days_per_week'),
       position('off_days_per_week' in pg_get_constraintdef((select oid from pg_constraint where conname = 'technician_attribute_history_field_check'))) > 0;
```

## Rollback

[20261102100000_rollback.sql](20261102100000_rollback.sql): drops both columns and their history rows; the trigger
goes back to its four fields.
