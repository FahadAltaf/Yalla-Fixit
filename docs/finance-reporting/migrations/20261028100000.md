# 20261028100000_technician_hours_history

Sami's answers on utilization (28 Oct): a working day is 8 hours (12 for some data centre staff), and a
report of a past period keeps the shift and team each technician had then.

- `technician_reference.daily_hours`: hours a working day, net of breaks. Null = the standard day in
  Settings → Reporting (8 h). Set on the technician in Scheduling → Technicians.
- `public.technician_attribute_history`: one row per change of shift, team leader, rest days or daily
  hours, with the Dubai date it takes effect. Written by a trigger on `technician_reference`, so edits made
  on live `main` are recorded too. The first change of a field also records the value it replaced, from
  2000-01-01. Seeded once from the Scheduling audit log (`technician_attributes_updated`: 378 rows
  from 178 logged edits since 7 Sep, counted 28 Oct).

Live-safe: one nullable column, one new server-only table, one trigger that only inserts into it (SECURITY
DEFINER, so an edit made with any role still records its history). No FK to `technician_reference`, so the
FSM technician sync behaves exactly as before. Until this is applied, the reports use each technician's
current values and the standard 8-hour day, and the technician dialog's daily-hours field is refused.

## Pre-check (expect `f | f`)

```sql
select exists (select 1 from information_schema.columns
               where table_schema = 'public' and table_name = 'technician_reference' and column_name = 'daily_hours') as has_daily_hours,
       to_regclass('public.technician_attribute_history') is not null as has_history;
```

## Apply

The file in the SQL editor. No schema to expose (it is in `public`).

## Post-check (expect one row: `t | t | t | f | n`, where `n` is the number of seeded rows, 378 on 28 Oct)

```sql
select exists (select 1 from information_schema.columns
               where table_schema = 'public' and table_name = 'technician_reference' and column_name = 'daily_hours') as has_daily_hours,
       to_regclass('public.technician_attribute_history') is not null                                   as has_history,
       exists (select 1 from pg_trigger where tgname = 'technician_attribute_history_on_update')        as has_trigger,
       has_table_privilege('authenticated', 'public.technician_attribute_history', 'SELECT')            as authenticated_reads,
       (select count(*) from public.technician_attribute_history where source = 'audit_seed')           as seeded;
```

## Rollback

[20261028100000_rollback.sql](20261028100000_rollback.sql): drops the trigger, its function, the history
table and the column. Daily hours entered since are lost; nothing else changes.
