# 20261020110000_people_reporting_fields

New columns on `technician_reference` (6), `user_profile` (1) and `leave_records` (1), and a new table
`org_public_holidays`. Every new column is nullable or defaults to today's behaviour (active, visible,
uncategorised), so live `main` is unaffected: its technician sync, leave form and user screens write the same
columns as before.

**Order: apply this before this branch's code runs anywhere** (a dev server on the branch included). The
branch's technician sync writes `technician_reference.email` and reads the new columns; without them the
roster refresh and the Technicians page fail. Live `main` is unaffected either way.

Tested on the [harness](../../../scripts/db-harness/README.md): applied twice; checks in
`checks/20_p1_people.sql`, including the live sync upsert and leave insert unchanged.

## Pre-check (expect one row: `0, 0, 0, f`)

```sql
select
  (select count(*) from information_schema.columns
     where table_schema = 'public' and table_name = 'technician_reference'
       and column_name in ('user_profile_id', 'email', 'employment_status', 'leaving_date',
                           'hidden_from_lists', 'rest_weekdays'))              as technician_cols,
  (select count(*) from information_schema.columns
     where table_schema = 'public' and table_name = 'user_profile'
       and column_name = 'hidden_from_lists')                                  as user_cols,
  (select count(*) from information_schema.columns
     where table_schema = 'public' and table_name = 'leave_records'
       and column_name = 'leave_category')                                     as leave_cols,
  to_regclass('public.org_public_holidays') is not null                        as holidays_exists;
```

Also note the row counts, to compare after: `select (select count(*) from public.technician_reference),
(select count(*) from public.user_profile), (select count(*) from public.leave_records);`
(20 Oct: 118, 17, 5).

## Apply

The file, in one transaction. The tables are small, so the column adds and the one unique index take no
noticeable lock. Never `supabase db push`.

## Post-check (expect one row: `6, 1, 1, t, 0, 0, 0`, and the same row counts as before)

```sql
select
  (select count(*) from information_schema.columns
     where table_schema = 'public' and table_name = 'technician_reference'
       and column_name in ('user_profile_id', 'email', 'employment_status', 'leaving_date',
                           'hidden_from_lists', 'rest_weekdays'))                   as technician_cols,
  (select count(*) from information_schema.columns
     where table_schema = 'public' and table_name = 'user_profile'
       and column_name = 'hidden_from_lists')                                       as user_cols,
  (select count(*) from information_schema.columns
     where table_schema = 'public' and table_name = 'leave_records'
       and column_name = 'leave_category')                                          as leave_cols,
  to_regclass('public.org_public_holidays') is not null                             as holidays_exists,
  (select count(*) from public.technician_reference
     where employment_status <> 'active' or hidden_from_lists)                      as changed_technicians,
  (select count(*) from public.user_profile where hidden_from_lists)                as hidden_users,
  (select count(*) from information_schema.role_table_grants
     where table_schema = 'public' and table_name = 'org_public_holidays'
       and grantee in ('anon', 'authenticated'))                                    as holiday_api_grants;
```

Live check: open Scheduling, add and then cancel a test leave entry for a test technician (or just open the
leave dialog if no test technician exists); open Users. Both behave as before.
