# 20261118150000_finance_invoice_guards

Two fixes from Sami's invoicing review (9 and 13 Nov 2026).

1. **The invoice limit is checked inside the database.** Two people recording an invoice on the same partly-done line
   at the same moment could together invoice more than Operations allowed: the limit was only checked in the server
   code. Each line now carries `max_invoiced` (the most it may have invoiced in total once this invoice is in), and
   `finance.record_line_invoice` checks it with the line locked. The second invoice waits for the first, then is
   refused with "reload to see the latest".
2. **MAHER total and a reason for a difference.** Finance enters the total printed on the MAHER invoice (the scan fills
   it in). It is kept in `finance.line_invoices.maher_total`. If it differs from the portal's total (lines plus VAT)
   by more than AED 1.00, a reason is required (`variance_reason`), enforced by the function and by a CHECK.

Live-safe: two nullable columns, a CHECK every existing row passes, and the function replaced with two extra
parameters that have defaults. The code live now calls it with its usual ten parameters and keeps working. One
transaction, idempotent.

**Order:** apply this before you push the code. (If the code goes first, it falls back to the old function: invoices
still record, but without the MAHER total, the reason or the locked limit check, until this is applied.)

## Pre-check (expect `0 | 10`)

```sql
select (select count(*) from information_schema.columns where table_schema = 'finance'
          and table_name = 'line_invoices' and column_name in ('maher_total', 'variance_reason')),
       (select max(p.pronargs) from pg_proc p join pg_namespace n on n.oid = p.pronamespace
          where n.nspname = 'finance' and p.proname = 'record_line_invoice');
```

```sql
          and table_name = 'line_invoices' and column_name in ('maher_total', 'variance_reason')),
       (select count(*) from pg_constraint where conname = 'line_invoices_variance_has_reason'),
       (select max(p.pronargs) from pg_proc p join pg_namespace n on n.oid = p.pronamespace
          where n.nspname = 'finance' and p.proname = 'record_line_invoice'),
       (select count(*) from pg_proc p join pg_namespace n on n.oid = p.pronamespace
          where n.nspname = 'finance' and p.proname = 'record_line_invoice');
```

The last figure is 1: only the new function exists (no old overload left behind).
